# Roadmap verification sweep — 2026-09-09, against the v2.11.5 tree

**Method**: every open item in `docs/development/roadmap.md` was extracted by a per-section reader,
then handed to an **independent adversarial verifier instructed to try to prove it ALREADY DONE,
STALE or SUPERSEDED** — `GENUINELY_OPEN` was only permitted after an attempt to discharge it failed.
Every verdict carries the literal command or `file:line` that establishes it; a verifier that could
not produce one was required to return `UNVERIFIABLE` rather than guess.

**Scale**: 10 section readers, 39 item verifiers, 1 completeness critic, 1 synthesis — 51 agents,
1,122 tool calls, no errors.

| Verdict | Count |
|---|--:|
| GENUINELY_OPEN | 21 |
| **STALE_PREMISE** | **15** |
| ALREADY_DONE | 3 |
| **Total items verified** | **39** |

⚠ **18 of 39 roadmap items did not survive contact with the tree.** Several were false in a way that
would have sent someone to do the *wrong work* — the epsilon tier's blocking gate could not be
executed at all, and the struct-layout contract quoted as protection for five releases cannot fail.

⭐ **This report is the evidence base for the strike-throughs now in `roadmap.md`.** The stale rows
were struck rather than deleted so the reasoning stays visible; the proofs live here.

### `STALE_PREMISE` — Decide whether the distlib bundle needs the public/private distinction

- **section**: v3 · **value**: medium · **effort**: low
- **proof**: Decisive probe (scratchpad project, repo untouched — `git status --porcelain` empty): `cyrius distlib` on a two-module [lib] where src/a.cyr holds `private` + `pub fn a_api` + `fn _a_helper` and src/b.cyr holds `pub fn b_api` calling `_a_helper`. - **detail**: The item's framing is refuted by measurement on the current pin, but the work itself has not been done.

WHAT IS STALE. The item (roadmap.md:271-273, introduced 2026-08-11 in commit 5d77b5f at pin 6.5.18) rests on two assertions that were true then and are not now: that hisab "signals intent by naming convention alone ... and nothing enforces it", and that the bundle may not need the distinction "since it concatenates everything into one compilation unit". At 6.6.2 cycc has a working, enforced visibility system, and CONCATENATION DOES NOT DISSOLVE IT:
  - `private` alone on a line makes the file private-by-default; `pub fn` inside it exports a symbol; plain `fn` inside it is rejected at the call site with `'X' is private to its file`.
  - `pub fn` in a file WITHOUT a `private` header is a harmless no-op (`cyrius check` → ok), so the marker pass is separable from the breaking flip.
  - `cyrius lint` = 0 warnings and `cyrius fmt --check` = rc 0 on a file using both, so adoption trips no CI gate.
I proved the composed case end to end against a real `cyrius distlib` bundle: the bundle exported exactly the `pub fn` symbols and rejected a consumer reaching `_a_helper`.

SO TWO OF THE ITEM'S THREE SUB-DECISIONS ARE PRE-ANSWERED BY THE TOOLCHAIN.
  1. "the visibility marker" — decided upstream. It is `private` (file header) + `pub fn` (per export). Per-item `private` is explicitly refused by cycc with its own diagnostic, so the roadmap's mental model of marking 269 individual functions private is not expressible; the granularity runs the other way (private by default, opt symbols OUT).
  2. "whether the distlib bundle needs the distinction at all" — the answer is that the bundle is the ONLY place it can be enforced for a consumer, and it works there today. The bundle is the sole surface a consumer touches; enforcement at the bundle boundary is exactly what the item doubted was possible.
  3. "whether those six pairs get a shared-internal escape hatch" — CONCATENATION IS THE HATCH, for free. In my probe `b_api` (from module b) called `_a_helper` (from module a) with no error, because after concatenation they are one file. All six `X`→`X_ext` pairs would keep working in the bundle unchanged. A hatch is only owed on the à-la-carte / `cyrius distlib --modular` path (`--modular` exists since 6.2.50 and emits `dist/<name>/{index.cyml,*.cyr}` — I ran it), where file boundaries survive and the private edge would break.

Every number the item quotes re-derives EXACTLY on today's tree at 2.11.5, so its sizing is current, not carried: 269 `_`-prefixed fn definitions across src/, 17 cross-module private calls, and the identical six-pair table (calc→calc_ext 3, calc→noise_simplex 2, geo_advanced→collision_core 4, lie→lie_ext 4, num→num_ext 2, symbolic→symbolic_ext 2).
